# 安装与使用

## 环境

该项目是已有 foobox 的覆盖层。先从 foobox 上游安装兼容的 DUI 配置和依赖；不要把它当作 foobar 裸安装的一键完整皮肤。作者本机基线为 foobar2000 2.25.3 x64、JSplitter 4.0.4.4-beta、ESLyric 1.0.6.2 Beta。

只用与播放器相同架构的组件。出现 `Not a valid Win32 application` 时先核对 x86 / x64，不要继续复制旧整合包的 DLL。

## 下载来源

1. **播放器**：中文用户可从 [Asion 汉化版作者发布页](https://www.cnblogs.com/asionwu/p/21537446) 获取安装资源；本机已使用版本为 **foobar2000 v2.25.10 x64**，这不代表其他版本已经验证。原版请到 [foobar2000 官方下载页](https://www.foobar2000.org/download) 获取。汉化与主程序归原作者，本项目不重新上传汉化安装程序。
2. **foobox 基础主题**：从 [foobox 8.8 发布页](https://github.com/dream7180/foobox-cn/releases/tag/8.8) 下载 `foobox_x64.cn.v8.8-1.exe`，再安装 JSplitter 4.3.4 和 ESLyric 1.0.6.2。8.14 已更改根脚本和分栏结构，当前不兼容。
3. **本项目覆盖层**：当前下载 [源码 ZIP](https://github.com/konghenfuxue-cpu/foobar-immersive/archive/refs/heads/main.zip)，解压后按本文说明运行 `Install.ps1`。这是需要现有 foobox 的主题覆盖层，不是解压即用的播放器。

**发布状态（2026-10-18）**：尚未提供主题安装器 EXE 或独立 Release 资源包。后续资源包将在 [本项目 Releases](https://github.com/konghenfuxue-cpu/foobar-immersive/releases) 提供；当前不要把该页面当成已有安装包下载入口。计划以主题配置安装包交付，播放器仍从上述来源获取；第三方组件按各自许可决定能否打包。托盘优化仍在本机测试，存在首次恢复页面空白的反馈，不能据此承诺固定内存占用或已解决恢复问题。

## 本轮固定基线

新安装按 [新手教程](BEGINNER.md) 使用 foobar2000 2.25.10 x64、foobox 8.8 默认布局、JSplitter 4.3.4、ESLyric 1.0.6.2。8.8 自带的两个组件过旧，必须更新。安装脚本新增 DLL 版本预检，避免仅凭脚本文件存在就继续覆盖。版本下限检查通过不代表新版本已经完成视觉验收。

## 目录和安装

1. 退出 foobar，定位配置目录。普通安装常见为 `%APPDATA%/foobar2000-v2`，便携版一般为安装位置内的 `profile`，以实际位置为准。
2. 运行仓库根目录 `Install.ps1 -ProfilePath '实际配置目录'` 查看检查结果；它默认不写入。
3. 确认原配置中的 foobox 脚本结构符合检查要求后，加 `-Apply`。安装仅复制 `overlay/` 文件，不修改数据库、音乐目录或原生主布局。
4. 打开 foobar。根控制脚本需使用 `foobox/script/js_panels/bottombar.js`。如果顶部没有四个标签，检查原 foobox 主题的根脚本入口；不要向未知面板盲目粘贴整份脚本。

安装会覆盖四份同名 foobox 脚本，并增加导航脚本和歌词/配色文件。请自行保留想继续使用的个人修改；安装器不备份整个配置。

## 布局兼容

根布局需要现有 list、brw、bio 等面板；音乐页内使用 SPLL / SPLR 主分栏、infoart / ESLProp，以及 TrackProp / ESLyric 子面板。源码中的名字来自本机原 foobox 布局。

上游 foobox 版本不同会改变面板结构，本覆盖层不保证自动适配任意主题。若出现面板名称不存在，恢复原脚本，按当前布局调整对应名称。

独立可视化入口已去除，但安装器不会删除原生布局中的隐藏面板或卸载组件。若原配置仍嵌入 MilkDrop 等可视化，应先在原生布局编辑器中移除相应面板，再卸载不使用的组件。不能因为按钮隐藏就认为组件已卸载。

## 沉浸歌词

1. 在 ESLyric 设置中启用自定义布局，选择 `FooboxImmersive`。若同时有私人旧布局同名，先将其中一个改名，避免选择混淆。
2. 启用 ESLyric 对外脚本控制：按当前 ESLyric 官方文档设置 `pref.script.expose`，或按文档创建组件开关文件，然后重启。
3. 点击顶部“沉浸歌词”。退出到“我的音乐”时恢复日常布局和分栏比例。

双语歌词需要来源文本中本来就有原文与译文，本主题不自动翻译或下载歌曲。无封面时公开布局不会加载别人的默认图片。

## 深浅配色

从2026-10-19起，`Install.ps1 -Apply` 默认将现有 `theme.fth` 的颜色区段替换为公开深灰橙色；其他布局、字体等区段逐字节保留。安装器校验FTH各区段MD5，并在颜色有变化时先保存 `foobox-theme-before-dark-日期时间.fth` 备份，再写入结果。默认只检查模式不写主题或备份。需要保留已有配色时加 `-KeepColours`；缺少 `theme.fth` 时先正常打开并退出已安装的foobox，不能拿只有颜色的文件直接替代完整主布局。

恢复颜色时，退出播放器后将该备份复制回配置目录的 `theme.fth`；备份包含当时完整主题，若此后改过布局，应优先导入浅色“仅颜色”文件，以免覆盖后来的布局修改。以下为手动切换方式：

首选项 → 显示 → 默认用户界面 → 导入主题，选择配置目录 `foobox/配色/深色-仅颜色.fth` 或 `浅色-仅颜色.fth`。两份文件只有颜色区段。沉浸页背景随深浅颜色调整，若未即时刷新，切换页面后再进入。

这些是公开版独立颜色定义，参考深灰橙色方向，未复制 foocolor 原主题二进制。

## 内存

封面图片、背景模糊、艺术家图片缓存与频谱都会占用内存。优先关闭不用的原生面板、减少封面缓存和高分辨率背景，再评估频谱；不承诺固定内存降幅。

## 已有配置升级播放器

2026-10-12 本机由 2.25.3 x64 升级到 Asion 2.25.10 x64 普通汉化版，用户“关于”截图确认版本。来源：[Asion 发布文章](https://www.cnblogs.com/asionwu/p/21537446)。这是一条已有配置升级记录，不是全新安装兼容性保证。

- 保持 x64 架构及原安装模式；本机使用标准模式，配置在 `%APPDATA%/foobar2000-v2`。独立试用应使用单独的便携配置，不能仅换安装目录就视为隔离。
- 退出播放器后升级原目录中的主程序，并同步更新安装器提供的内置组件，特别是“转换器”和“文件操作”。不能一概取消所有可选组件：旧内置组件残留可能触发“组件来自 foobar2000 其他版本”。
- 保留现有配置；不勾选覆盖“配置文件 / 转换器配置 / ESLyric 配置”，不整包覆盖 Plus 的 foobox 脚本和主题。
- 第三方组件分别核对架构和兼容性；普通版主程序升级不会自动证明 JSplitter、ESLyric 已升级。
- 重启后核对版本、组件错误、四页面切换及播放情况。安装完成和“关于”版本正确不等于长期播放已稳定。

## 已知稳定性观察

旧主程序 2.25.3 x64、JSplitter 4.0.4.4-beta 的私人配置曾在连续播放中崩溃。日志定位于 `mozjs-lur-128`，异常 `C0000005`，涉及 JavaScript 内存回收相关调用；具体触发脚本尚未确认。此记录不证明公开覆盖层必然触发该问题，也不证明升级主程序已修复。个人崩溃日志与转储不上传。

## 升级 JSplitter

2026-10-12 本机独立便携配置升级至 JSplitter 4.3.4 x64，用户反馈持续播放正常后迁入正式版。此次只迁移组件，保留正式版原有歌单、布局及其他配置。

1. 完全退出 foobar2000，备份现有 JSplitter 组件目录；备份放在组件扫描目录之外。
2. 从 [官方 4.3.4 发布页](https://github.com/dima-lur/jsplitter/releases/tag/v4.3.4) 获取组件，按播放器架构安装。手动解包时不要把 x86 DLL 放进 x64 配置。
3. 更新主组件及配套 JavaScript 引擎，避免混用旧引擎；本机由 mozjs-lur-128 切换至 mozjs-lur-153。
4. 保留自行添加的脚本包。若简介面板引用位于旧组件 `samples/packages` 下的自定义包，应一并保留；缺失时可能出现 `Package not found`。本机保留了 WilB 简介汉化包，不在公开仓库重新分发该包。
5. 启动正式版，检查组件版本、四页面、简介及持续播放。正式版仍有问题时，退出播放器，将新组件目录移出扫描范围，再恢复完整旧备份。

独立环境的用户测试回执与文件校验不替代公开覆盖层在全新配置中的运行验证。测试副本可在正式版稳定后清理，旧组件备份建议暂时保留。
